# 2026-09

## 2026-09-02 作業概要

MPS08B（Futaba 金型内圧計測システム）のピーク値トレンドモニタを新規に立ち上げた。調査からPhase 1〜3相当の実装まで一日で完走。

### 経緯

MPS08B 本体アプリ（PPSB v1.3.0.5）が成形機と連動してショットごとに圧力波形を記録している。本体は波形表示が主眼でショット間の推移を追えないため、直近Nショットのピーク値を履歴付きで見たいという要求から始まった。

途中で **純正のトレンドビューア（`TrendViewerSetup.msi`）が未インストールのまま置いてあった**ことが判明し、まずそれを評価した。

### 純正トレンドビューアの評価

インストール時に2つの落とし穴を踏んだ。

1. **msi に exe が2本入っている**。`TrendViewer.exe` v1.1.1.3（2023-12ビルド）と `TrendViewerForMPS08B.exe` v1.2.3.7（2025-11ビルド）。**インストーラが作るデスクトップショートカットは古い方を指している**。旧版は MPS08（B なし）世代の CSV フォーマットを前提にしており、`ALL_*.csv` の1行目 `Time:2026/09/01 13:55:46` を数値行だと思って `DataLineRead()` で `InvalidCastException: String "Ti" から型 'Integer' への変換は無効です` で即死する
2. 新版を直接起動すると「統計データファイルが変更され、時刻情報がありません」というダイアログが出るが、「はい」で進めば動く

**結論: 純正はリアルタイム更新する。だが数値がグラフに一切出ない。** 値を知るにはグラフ上をクリックしてステータスバーに1点だけ表示させる必要がある。横軸は `0,1,2...` の連番で実ショット番号が出ず、未使用の CH03〜CH08 がゼロのまま統計表を占領する。この一点が決定的に使えないため自作を継続した。

なお「フォーマットが変わったから警告が出ているのでは」という仮説を立てたが、実測で **2026-02-16 から 2026-09-02 まで全36フォルダで104列・完全に不変**であることを確認して棄却した。

### データ源の調査結果

サマリ CSV（`<設定名>_<日付>/<設定名>_<日付>.csv`）だけで足りる。**ピーク値は既に計算済みで `CH01_peak` / `CH02_peak` 列に入っている**ため、390KB の生波形を毎回パースする必要はない。

実装前に潰した不確定要素:

- **計測中でもロックされず読める**。Windows .NET の `FileShare.ReadWrite` でオープン成功、WSL 経由の read も成功
- **ショット完了ごとに即追記される**。純正ビューアがリアルタイム更新できていることで実証

### 実データで見つけた罠（すべて実測）

| 罠 | 実測値 |
|---|---|
| ヘッダ行がファイル途中に何度も再挿入される（計測の中断→再開ごと） | `20260821_setting001_20260831.csv` は247行中ヘッダ**6回**。全36ファイル中17ファイルで2回以上。素朴に `csv.DictReader` へ渡すと落ちる（実際に落とした） |
| ショット番号は飛ぶが巻き戻らない | 241データ行で重複ゼロ・非単調ゼロ。中断で最大21ショット欠落、時刻も4時間飛ぶ |
| フォルダ名ソートは必ず誤答する | `separate_20260219` / `_20260828` / `DefaultFile001_20260216` が実在。同日2フォルダ併存（`20260821_setting001_20260902` と `20260902_setting001_20260902`）も実在 |
| `interval` は固定でない | 939件で min 0.0 / 中央値 32.6 / **最大 1,288,852秒（約15日）**。100秒超が333件 |
| CRLF・末尾カンマ・0行CSV | 最終列は常に空。データ0行のサマリCSVが10ファイル実在 |

**当初「成形サイクル約22秒」と判断したのは誤りだった**。連続成形中の1日分だけを見ていたためで、中断を挟むと桁で変わる。監視状態の判定に固定閾値を使えないので、直近10ショットの interval 中央値×3（90〜600秒でクランプ）に変更した。

さらに調査中に**ユーザーがアプリ一式を `Desktop\フォルダー\` から `Documents\` へ移動した**。絶対パスのハードコードが即座に破綻する環境であることが実地で証明されたため、MMS_DATA のパスは設定ファイルで持ち GUI から変更できるようにした。

### 実装

`core/` に tkinter を一切 import しない構成にして、判断ロジックを `MonitorService.poll()` に閉じ込めた。GUI なしで pytest から全部検証できる。

検証結果:
- 単体テスト 29件（不完全行・ヘッダ再挿入・トランケート復帰・mtime判定など）
- **実データ36ファイル・955ショットを全件パース、スキップゼロ・取りこぼしゼロ**
- ヘッダ6回のファイルで241件正しく読み、中断5箇所を検出
- 冪等性（reset して読み直しても件数不変）を実データで確認

### GUI で踏んだこと

- 初回起動時、`chart.pack(expand=True)` を先に書いたせいでウィンドウが縮んだときにテーブルが下から切られた。**下段を `side="bottom"` で先に確保してから残りをグラフに与える**のが正解
- CH01 と CH02 の値が近いと最新値ラベルが重なって読めなくなる。近接時だけ上下に振り分ける処理を追加（大小関係は保つ）
- 中断が近接すると「中断 21ショット欠」のラベル同士が重なる。テキストを `21欠` に短縮し、x が近い場合は段を下げるようにした
- `ttk.Frame` に `height=` を指定しても効かない。Treeview 側に `height=<行数>` を渡す

### 環境メモ

- Windows 側 Python は **3.12.8**（`C:/Users/<user>/AppData/Local/Programs/Python/Python312/python.exe`）。**scoop に python は入っていない**（7zip/ffmpeg 等のみ）
- WSL のコードを Windows Python から直接動かせる: `\\wsl.localhost\<distro>\home\<user>\ClaudeCode\shot-monitor\app.pyw`
- `Start-Process` に `-RedirectStandardOutput` を付けると GUI プロセスの終了まで PowerShell が返らずタイムアウトする。リダイレクトなしで起動し、ログはアプリ側でファイルに書く
- snap 版 `gh` の `repo create --push` は `git: 'remote-https' is not a git command` で失敗する。リポ作成と remote 設定までは成功するので、push だけ素の git で行えばよい
