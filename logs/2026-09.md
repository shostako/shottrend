# 2026-09

## 2026-09-02 作業概要

MPS08B（Futaba 金型内圧計測システム）のピーク値トレンドモニタを新規に立ち上げた。調査からPhase 1〜3相当の実装まで一日で完走。

### 経緯

MPS08B 本体アプリ（PPSB v1.3.0.5）が成形機と連動してショットごとに圧力波形を記録している。本体は波形表示が主眼でショット間の推移を追えないため、直近Nショットのピーク値を履歴付きで見たいという要求から始まった。

途中で **純正のトレンドビューア（`TrendViewerSetup.msi`）が未インストールのまま置いてあった**ことが判明し、まずそれを評価した。

### 純正トレンドビューアの評価

インストール時に2つの落とし穴を踏んだ。

1. **msi に exe が2本入っている**。`TrendViewer.exe` v1.1.1.3（2023-12ビルド）と `TrendViewerForMPS08B.exe` v1.2.3.7（2025-11ビルド）。**インストーラが作るデスクトップショートカットは古い方を指している**。旧版は MPS08（B なし）世代の CSV フォーマットを前提にしており、`ALL_*.csv` の1行目 `Time:2026/09/01 13:55:46` を数値行だと思って `DataLineRead()` で `InvalidCastException: String "Ti" から型 'Integer' への変換は無効です` で即死する
2. 新版を直接起動すると「統計データファイルが変更され、時刻情報がありません」というダイアログが出るが、「はい」で進めば動く

**結論: 純正はリアルタイム更新する。だが数値がグラフに一切出ない。** 値を知るにはグラフ上をクリックしてステータスバーに1点だけ表示させる必要がある。横軸は `0,1,2...` の連番で実ショット番号が出ず、未使用の CH03〜CH08 がゼロのまま統計表を占領する。この一点が決定的に使えないため自作を継続した。

なお「フォーマットが変わったから警告が出ているのでは」という仮説を立てたが、実測で **2026-02-16 から 2026-09-02 まで全36フォルダで104列・完全に不変**であることを確認して棄却した。

### データ源の調査結果

サマリ CSV（`<設定名>_<日付>/<設定名>_<日付>.csv`）だけで足りる。**ピーク値は既に計算済みで `CH01_peak` / `CH02_peak` 列に入っている**ため、390KB の生波形を毎回パースする必要はない。

実装前に潰した不確定要素:

- **計測中でもロックされず読める**。Windows .NET の `FileShare.ReadWrite` でオープン成功、WSL 経由の read も成功
- **ショット完了ごとに即追記される**。純正ビューアがリアルタイム更新できていることで実証

### 実データで見つけた罠（すべて実測）

| 罠 | 実測値 |
|---|---|
| ヘッダ行がファイル途中に何度も再挿入される（計測の中断→再開ごと） | `20260821_setting001_20260831.csv` は247行中ヘッダ**6回**。全36ファイル中17ファイルで2回以上。素朴に `csv.DictReader` へ渡すと落ちる（実際に落とした） |
| ショット番号は飛ぶが巻き戻らない | 241データ行で重複ゼロ・非単調ゼロ。中断で最大21ショット欠落、時刻も4時間飛ぶ |
| フォルダ名ソートは必ず誤答する | `separate_20260219` / `_20260828` / `DefaultFile001_20260216` が実在。同日2フォルダ併存（`20260821_setting001_20260902` と `20260902_setting001_20260902`）も実在 |
| `interval` は固定でない | 939件で min 0.0 / 中央値 32.6 / **最大 1,288,852秒（約15日）**。100秒超が333件 |

**当初「成形サイクル約22秒」と判断したのは誤りだった**。連続成形中の1日分だけを見ていたためで、中断を挟むと桁で変わる。監視状態の判定に固定閾値を使えないので、直近10ショットの interval 中央値×3（90〜600秒でクランプ）に変更した。

さらに調査中に**ユーザーがアプリ一式を `Desktop\フォルダー\` から `Documents\` へ移動した**。絶対パスのハードコードが即座に破綻する環境であることが実地で証明されたため、MMS_DATA のパスは設定ファイルで持ち GUI から変更できるようにした。

### チャンネル数の可変化

「現状 2ch だが、能力としては本体アプリの最大数（32ch）を受け入れられるようにすべき」という要求で、データ層から可変化した。

- `Shot.peaks: tuple[float, ...]`。ヘッダの `CHnn_peak` を CH01 から連番で探し、見つかった分だけ読む
- **未接続 ch も本体は 0.00 で書き続ける**ので、列の有無では使用中か判別できない。`used_channels()` が「一度でも非ゼロだった ch」を返す
- ch が 4 本以上でカードが小型版に自動切替、5 枚ずつ折り返し
- 色は `init.xml` の waveColor 8 色を巡回。ただし**明るい地では黄・シアン・緑が読めない**ので、文字用に沈めた版を別に持つ

`tools/fake_writer.py` に `--channels` を足し、8ch のダミーデータを生成して実際に画面に出して確認した。作っただけで動かさない状態を残さないため。

### tkinter で踏んだ罠

1. **`tk.Canvas` のサブクラスで `self._options` という属性名は使えない。** `tkinter.Misc` が内部で `self._options(cnf)` を呼ぶため `TypeError: 'list' object is not callable` で初期化ごと死ぬ。属性の代入は必ず `super().__init__()` より後に行う
2. **`pythonw` 起動では stderr がどこにも出ない。** 上記の例外が「起動しない」としか分からず原因究明が止まった。`app.pyw` の `main()` に例外捕捉を入れてログに残すようにして初めて見えた
3. **`ttk.Frame` に `height=` を指定しても効かない。** 行数を決めたいときは `ttk.Treeview` 側に `height=<行数>` を渡す
4. **セグメント状のボタンを Canvas に描くときは、塗りを全部置いてから線を引く。** 1 つずつ「枠付きで」描くと、端の角丸を四角く戻す塗りが隣との境界線を消す。実際にユーザーから「右 2 項目の境界線が無い」と指摘されて発覚した
5. **`Treeview` には列の右パディングを付ける手段がない。** 最後の列の数値が枠に張り付くのは、幅 16px の空列を末尾に足して回避した
6. **pack の順序**: 下段を先に `side="bottom"` で確保してから、残りを `expand=True` に与える。逆にするとウィンドウが縮んだとき下段から切られる

### exe で踏んだこと

1. **`excludes` の自爆。** 軽くするつもりで `urllib` / `email` / `http` / `ssl` などを除外したら、`pathlib` が 3.12 で `urllib.parse` を import するため起動時に `ModuleNotFoundError: No module named 'urllib'` で死んだ。windowed の exe は「Unhandled exception in script」のダイアログしか出さず、ログを書く前に落ちるので `logs/app.log` も無い。console=True にした一時 spec を組んでトレースバックを取って判明。除外は `pytest` / `unittest` / `pydoc` 程度に戻した。数 MB の節約に見合わない
2. **PowerShell 5.1 のエンコーディング。** spec を `Get-Content | -replace | Set-Content` で加工したら cp932 で読み書きされて UTF-8 のコメントが壊れ `SyntaxError: (unicode error)`。`-Encoding UTF8` 必須
3. **`Set-Content -Encoding UTF8` は BOM を付ける。** それで書いた `config.json` を `json.loads(read_text("utf-8"))` が `Unexpected UTF-8 BOM` で拒否し、既定値に落ちてデータフォルダを聞くダイアログが出た。メモ帳で編集しても同じ BOM が付くので `utf-8-sig` で読むよう直した。テストも追加
4. **frozen 判定は 2 箇所。** `core/config.py` の `app_dir()` は最初から frozen 対応していたが、`app.pyw` の `APP_DIR = Path(__file__).parent` はそのままで、onefile だとログが一時展開先に書かれて消えるところだった。exe の動作確認は空フォルダに exe と config.json だけ置いて行い、`logs/` が exe の隣にできることを確認する

v0.2.0 のタグを打ったら Release ジョブが落ちた。CHANGELOG から該当節を抜いてリリース本文にする Python を書いていて、それを `print` してリダイレクトしていたのが原因。**windows-latest の Python は stdout が cp1252** なので日本語で `UnicodeEncodeError`。`open(..., encoding="utf-8")` でファイルに直接書き、`PYTHONUTF8: "1"` を足して直した。タグは削除して打ち直し。

### ShotTrend への改名（PR#8）

`shot-monitor` は「フタバの MPS08B 専用ツール」に見えるが、実際に読んでいるのは 1 ショット 1 行の CSV でしかない。他社の測定機に広げる予定は今は無いが、名前で自分を縛る必要も無いので `ShotTrend` にした（表示名は CamelCase、パッケージとリポは `shottrend`）。パッケージも `shottrend/core` `shottrend/ui` に移した。

移動で `app_dir()` が壊れた。`Path(__file__).resolve().parents[1]` のままだったので、階層が 1 つ深くなった分だけ `shottrend/` を指す。Codex が P2 で拾った。`parents[2]` に直したが、**そのとき書いたテストが失敗したまま push された**。原因は `pytest -q | tail -1` で通したこと。パイプは最後のコマンドの終了コードしか返さないので、テストが赤でも `&&` の後ろが走る。`set -o pipefail` を入れる。

### public 化（PR#9）

MIT ライセンスを置き、README にフタバの商標に関する断りを書き、スクリーンショットを `tools/fake_writer.py` の擬似データで撮り直した。CLAUDE.md と作業ログの個人パスも `<user>` / `<distro>` に置き換えた。

**PEP 639 で CI が落ちた。** `pyproject.toml` に `license = "MIT"`（SPDX 式）を入れたまま `classifiers` の `License :: OSI Approved :: MIT License` を残していて、setuptools 77 以降はこの併用を `InvalidConfigError` で拒否する。厄介なのは**ローカルで再現しないこと** — 既存の `.venv` は入れ直さないので、クリーンな環境で `pip install -e .` を走らせる CI で初めて出る。classifier 側を消し、`build-system.requires` の下限も 77 に上げた。修正前後をクリーン venv で回して、落ちる／通ることを両方確認した。

この件、Claude の自動レビューは「PEP 639 記法で、ビルド分離環境では最新 setuptools が使われるので問題にならない**想定**」と書いていた。その最新 setuptools が拒否した行だ。レビューの「〜な想定」は検証ではない。

### force push では消えないもの

Codex が P1 で「tip を綺麗にしても親コミットは到達可能なままだ」と指摘してきた。調べたらもっと悪くて、**GitHub は PR に紐づいたコミットを `refs/pull/<n>/head` として保持し続け、default branch を force push しても消さない**。実際に `git fetch origin refs/pull/6/head` したら、旧スクリーンショットの blob も個人パス入りの CLAUDE.md もそのまま生きていた。public にすればこの ref は誰でも読める。

対処として、`git filter-repo` で履歴を浄化した上で**リポジトリごと削除して同名で作り直した**。手順と検証:

1. `~/shottrend-archive/` に PR#1〜#9 の全会話（Claude・Codex のレビュー内容込み）、Release ノート、`git clone --mirror` の完全ミラーを退避
2. `--replace-text` で個人パスを置換、`--blob-callback` で旧スクリーンショットの blob を新しいものに差し替え（`--replace-text` はテキスト用で、画像の差し替えには使えない）
3. **本番前に mirror のコピーでリハーサル**し、書き換え前後で `git rev-parse <tip>^{tree}` が一致することを確認。ツリーハッシュが同じなら tip の内容は 1 バイトも変わっていないと言い切れる。あわせて全コミット走査で個人パスがゼロ件、旧 blob が到達不能であることも確認
4. 旧リポを削除 → public で新規作成 → `push --tags`

作り直した後の後始末が 3 つ。**secret は write-only なので値を移せない**（`CLAUDE_CODE_OAUTH_TOKEN` を手で入れ直す。`claude setup-token` で発行して `gh secret set`）。Codex コネクタも再連携。そして **master とタグを同時に push すると Release ワークフローが発火しない** — タグを削除して打ち直したら走った。

他 PC の clone は履歴が完全に別物になるので、`git fetch origin && git reset --hard origin/master` するか clone し直すこと。

### 多言語対応の設計

**翻訳表は言語ごとの Python dict モジュール**にした。JSON にすると `shottrend.spec` の `datas` と
`sys._MEIPASS` 分岐が要り、gettext は `.mo` のビルド工程が要って「`py app.pyw` で動く」が壊れる。
dict モジュールなら spec を一切触らずに済む。

**`importlib.import_module()` のような動的 import は使わない。** PyInstaller の静的解析から見えず、
ソースでは動くのに exe だけ `ModuleNotFoundError` で落ちる。windowed なので理由が出ない
（`excludes` の巻き添え死と同型）。5 言語をレジストリで静的 import する。

**切替は画面の丸ごと再構築**（`MonitorApp._rebuild_ui()`）。ウィジェットごとに `retranslate()` を
配る案は捨てた。`control_bar._group()` と `header_panel` の見出しは**参照を保持しない匿名ラベル**で、
その方式だと「ラベルを足したとき retranslate に足し忘れる」バグが構造的に残る。レビューでは
見つからず現場で気づくたちの悪さなので、起こりえない作りにした。`root` 直下のウィジェットと
destroy 対象の対応は `ast` でテストが見張る。

**core から日本語を剥がした。** `MonitorService.poll()` が返していた日本語の散文を翻訳キー
（`MSG_NO_ROOT` 等）とパラメータに変えた。翻訳キーは `STATUS_RUNNING` と同種の不透明な識別子で
表示文字列ではないので、core に置くのは層違反ではない。これで core のテストが表示言語に依存しなくなる。

### 公式アプリからの対訳抽出

MPS08B 本体（`MPS08B_Application_1_3_0_5.exe`）は WPF アプリで、5 言語分の `ResourceDictionary` が
コンパイル済み BAML として `.g.resources` に埋まっている。標準ライブラリだけで読めた。

- `.NET` の `.resources` は magic `0xBEEFCACE`。ヘッダを辿ると名前とストリーム位置が引ける
- **BAML の可変長レコードのサイズ欄は、種別バイトを含まず、サイズ欄自身は含む。** 実データで確認
  （`AssemblyInfo` の総長 80 バイトに対しサイズ欄は 79）。ここを取り違えると 1 件も拾えない
- 値は `0x11 TextWithConverter`。文字列の後ろに int16 のコンバータ ID が付く。`0x10` の素の Text と
  混同すると全滅する
- `x:Key` は `0x20 StringInfo` に名前、`0x26 DefAttributeKeyString` に「名前 ID → 値の相対位置」

**`VL_N00`〜`VL_N08` が ShotTrend の表示項目 9 つと完全に一致していた。** 残る 2 つは
`SW_RisingTime` / `SW_FallingTime`。日本語も本体に合わせて「立上り時間 → 上昇時間」
「立下り時間 → 下降時間」に直した。

公式訳には機械翻訳由来の壊れたものが混じっている。直したのは意味が違う 6 件だけ:

| キー | 言語 | 公式 | 問題 |
|---|---|---|---|
| `MT_Item` | 繁・簡 | 物品 | 商品の意 |
| `MT_Item` | ko | 안건 | 議案 |
| `MW_About` | ko | 약 | 「約」 |
| `Integral` | ko | 완전한 | 「完全な」 |
| `times` | ko | 타임스 | times の音写 |
| `SW_FallingTime` | 簡 | 上升时间 | **上昇時間**。逆の意味 |

韓国語の `SW_FallingTime`（떨어지는 시간）は座りが悪いが意味は通るので**直さない**。「語感が古い
程度なら公式のまま」の線引きに従った。

**本体アプリの文字列は他社の著作物なので、公開リポには ShotTrend が実際に引いている 17 キーだけ
置く**（`CITED_KEYS`）。全 352 件は `--all` で手元に出す。

### 見つけた既存バグ

- **項目コンボで単位が切れていた。** `width=11`（＝「0」11 文字分 = 77px）固定で、11 項目すべてが
  それより長い。「区間積分1 [MPa·s]」は「区間積分1 [」までしか見えていなかった
- `shot_table.py` の `COMPOSITE_LABELS.get(mode, "最大")` というハードコード fallback

### 英語で初めて露見したもの

**コントロールバーが 1000px に収まらない。** 英語の要求幅は 1107px で、`Range` が切れて `Delta` の
チェックボックスは枠の外に出ていた。日本語が 962px でぎりぎり収まっていただけの話。言語ごとに
最小幅の表を持つのではなく、**組み上がったバーの要求幅を測って `minsize` を決める**ようにした
（`_apply_min_size()`）。コントロールを足したときも自動で追随する。

### レビューで拾われたもの

**`theme.set_language_font()` を誰も呼んでいなかった**（Codex 指摘、9/3）。PR2 の中身が丸ごと
死にコードで、呼び出し元はテストのみ。日本語環境では既定値がたまたま正しいので画面は正常に見え、
スクリーンショット確認をすり抜けた。教訓は `~/.claude/agent-memory/monday/` に記録済み。

**訳文を先に作って持ち回っていた。** 状態帯の案内文は `t("menu.file")` の結果を
`_last_msg_params` にキャッシュしていたので、言語を切り替えて画面を組み直しても、そこだけ
切替前の言語で描かれる。次のポーリング（最大 60 秒）まで直らない。`i18n.Ref` を足して
「別の文言への参照」として渡し、`t()` が整形の直前に引き直すようにした。

**抽出ツールに 4 件。** すべて根は同じで、BAML のレコード種別を全部モデル化せずバイト単位で
総当たり走査していることに由来する。

1. **`.resources` の 8 バイト境界をファイル上の絶対位置で丸めていた。** 境界はストリーム先頭から
   数える。実データで 31 個のリソースセットのうち **12 個しか読めていなかった**（→ 31 個）。
   BAML が入っているセットがたまたま 8 の倍数から始まっていたので出力は正しく、気づかなかった
2. README の項目表だけ「立上り時間」のまま取り残された。README と日本語カタログを突き合わせる
   テストを足した
3. `10 02 00` は「空の Text」として検証を通る。これが値の並びより手前にあると全キーがずれる
4. 3 の対策として「全キーが解決できる候補」を要求したら、今度は**偽の Key が 1 つ混ざるだけで
   言語ごと落ちる**ようになった。脆さの向きを変えただけ。最終的に「最も多くのキーを解決できる
   候補」を採る**多数決**に落とした

4 で入れた「解決数が過半数か」の閾値は、変異注入したところ検出できるテストが書けず、書こうと
すると「実キーが少ない表を正当に落とす」ことを主張するテストになったので**外した**。走査が
失敗すれば `main()` の `CITED_KEYS` 検査（言語ごと）が必ず捕まえる。テストで守れない条件を
コードに残さない。

### 検証の手

**WSLg で GUI を起動し、Windows 側の PowerShell で画面を撮る**手が確立した。以後の目視確認が
WSL 内で完結する。

**PowerShell のデリゲート内で `Write-Output` はパイプに乗らないし、`$script:` への代入も効かない。**
`EnumWindows` のコールバックを PowerShell のスクリプトブロックで書くとウィンドウが 1 つも
見つからない。C# 側（`Add-Type -TypeDefinition`）で列挙を完結させ配列を返す形にする。
DPI は `SetProcessDPIAware()` を先に呼ぶ。

**exe をビルドして空フォルダで起動**するところまでやった。翻訳モジュールが PYZ に入っている
証明になる（動的 import を混ぜていればここで必ず落ちる）。5 言語とも豆腐なし、レイアウト崩れ
なし。最小幅は言語ごとに 1000 / 1010 / 1047px と変わる。

**新しいテストは複製ツリーで変異注入して検出力を確認する**運用を通した。destroy 漏れ、StringVar を
ローカルに、`apply_ttk_theme` を飛ばす、`after_cancel` を消す、絶対位置で丸める、サイズ欄の解釈、
最小位置を先頭に、全キー解決を要求、和集合で検査 —— どれも対応するテストが落ちることを確認した。

### ハーフスナップが最小幅で止まる（v0.4.1）

「Win+← で半分にすると半分より少し大きい」との報告。コントロールバーを 1 行固定にしていた
ため、その要求幅（日本語 1092px、英語 1233px）がそのまま `minsize()` → `WM_GETMINMAXINFO`
に流れ、1920px 画面の半分 960px より大きかった。バーを「ラベル＋操作部」の単位で折り返す
（`ui/flow.py` の `pack_rows`、tkinter 非依存でテスト可）ようにし、最小幅は最も広い単位の分だけに
した。ヘッダのセッション選択も上段に収まらなければ 2 段目へ。Codex が「4ch 以上の小型カードが
固定 5 列で 978px を要求する」と正しく指摘したので、そちらも同じ計算で段分けにした。手元の
実データが 2ch だったので、`tests/conftest.py` の `data_line` で 5ch の合成 CSV を作って再現した。

**PowerShell は DPI 非対応なので `GetWindowRect` が論理ピクセルを返す。** `SetWindowPos` で 960 を
要求して 960 が返ってきたのは 1200px の嘘だった。`SetProcessDPIAware()` を先に呼んで取り直す。
`keybd_event` で Win+← を送るとスタートメニューだけ開いて矢印が届かない。`SetWindowPos` で
物理 960px を要求すれば `DefWindowProc` が最小サイズで押し戻すので、スナップと同じ検証になる。
